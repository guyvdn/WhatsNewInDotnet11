Part one

C# 15

No more default case that hides the one you forgot

Unions are the headline of the whole release. Spend the time here.

Union types

Step 1: the case types are just records — they don't share a base class. Step 2: assignment converts implicitly. Step 3: the switch is exhaustive, so no default case. Under the hood it lowers to a struct with an object? Value property, so value-type cases are boxed — worth knowing for hot paths. Next slide: the way around it.

Unions without boxing

Same pets, but as value types — with records (classes) there is nothing to box. Step 1: the union keyword would store each one as object?, a box per value. Step 2: [Union] plus IUnion, both in System.Runtime.CompilerServices; this is what the union keyword generates for you. Step 3: one field per case and a tag, where 0 means default, no pet; the public constructors are what make Cat, Dog and Bird the case types, and they give you the same implicit conversions. Step 4: the non-boxing access pattern — the switch on the previous slide now calls TryGetValue, so it compiles unchanged and allocates nothing. Step 5: Value is still required; it boxes, but only when someone asks for it. Measured on GA: the union keyword allocates 24 bytes per match, this one zero. Runnable in examples/NonBoxingUnion.

Unions as results

This is where unions will show up most: the response type of a mediator or CQRS handler. Step 1: the result type lists every outcome. Step 2: the handler returns plain records, no exceptions for control flow and no OneOf or FluentResults package. Step 3: the endpoint has to map every outcome to HTTP; add a fourth case later and this switch warns until you handle it. With MediatR it's the same: IRequest<CreateOrderResult>. Runnable version in examples/ResultUnion (201, 400 and 404, checked on the released SDK).

The compiler has your back

Program.cs Pets.cs ⚠ 1 warning
click the 💡 — or press B
The warning text is verbatim from a GA build (11.0.100). The point: add a fourth case to Pet and every switch in the solution lights up. With an interface or a base class you'd have a silent default case instead. Add TreatWarningsAsErrors for CS8509 and it's a build break. One honest caveat: a default union holds null — an uninitialized field or array element — and then this "exhaustive" switch throws SwitchExpressionException with no warning. Add a null case, not _ =>, so a new case still warns. Checked on the released SDK.

Unions on the wire

Value
ASP.NET Core: union bodies in Minimal APIs & MVC OpenAPI: anyOf
Deserialization picks the case by JSON token kind: number means int, string means string. Two object cases need a classifier; the structural one matches on root-level property names. No match or two matches throws JsonException. If two cases have the same shape, say Dog(Name) and Cat(Name), nothing in the JSON can tell them apart: the structural classifier refuses the union with NotSupportedException on first use, before reading any JSON. The union writes no "$type", so the JSON has to carry the signal itself (last variant): each case gets a Type property, and ByType is a small JsonTypeClassifierFactory that reads "Type" and returns the union case with that name, or null, which the serializer turns into a JsonException. The classifier gets its own copy of the reader, so reading ahead doesn't consume the value. Full code in examples/Dotnet11Demo/Unions.cs. If you own the format and don't need a union, a class hierarchy with JsonDerivedType writes "$type" for you. Not supported: route/query/header/form binding, MessagePack, Newtonsoft.

Closed hierarchies

closed implies abstract, and it is not transitive: mark intermediate types closed too.

Same exhaustiveness, but for your own type family that shares members through a base class. Leave out the Refunded case and you get the same CS8509 as on the union slide, which I checked on GA. Union or closed? A union's cases can be any existing types (int, string, third-party) with no shared members; it's a struct and boxes value-type cases. A closed class's cases are your own derived types sharing a base. Rule of thumb: where you'd write OneOf<A, B> or a Result type, it's a union; where you'd write an abstract base and a few records, it's closed.

Part two

Runtime

No more state machines cluttering your stack traces

Same source code, a different implementation underneath.

Runtime Async opt-in

runtime-async
frames 0 the .NET libraries already ship compiled with it
Measured on GA (11.0.100) with examples/RuntimeAsyncDemo: 13 frames off, 5 on. Frame names are shortened for the slide. Be honest about it: exception stack traces already looked like this; the win is in live stacks — profilers, the debugger's call-stack window — plus fewer allocations. No longer preview at GA: no EnablePreviewFeatures needed, but still opt-in for your own code. The framework libraries already use it, so test AsyncLocal and ExecutionContext-heavy code on upgrade.

Faster without code changes

JIT (compiles as the app runs)

Fewer array bounds checks (values[^1], i + c < len), more virtual calls turned into direct calls

ReadyToRun (pre-compiled libraries)

up to 20×

faster collections: EqualityComparer<T>.Default now ships pre-compiled

NativeAOT (whole app compiled ahead of time to machine code)

Smaller, faster interface calls

Hardware

Half uses the CPU’s 16-bit float instructions where available, Math.BigMul is one instruction

Diagnostics

In-process crash report with the managed stack on Linux/macOS: DOTNET_EnableCrashReport=1

Baseline raised

x64 needs x86-64-v2 (roughly any CPU since 2009), Windows Arm64 needs LSE atomics

The "20x" is Microsoft's number from the runtime what's-new page, not mine. The baseline change: old CPUs fail at startup with "The current CPU is missing one or more of the baseline instruction sets" — check ancient build agents and VMs with restricted CPU flags.
Part three

SDK & CLI

No more .csproj just to write a real tool

File-based apps arrived in .NET 10. In 11 they become usable for real tools.

File-based apps: #:include

PS tools> dotnet run app.cs -e GREETING=hi Hello, Ada! PS tools> dotnet format app.cs PS tools> dotnet reference add --file app.cs ../Lib/Lib.csproj
  • Split across files, reference DLLs; an unchanged app relaunches without a rebuild
  • A new code-analysis warning (CA2266) wants the #! line on the entry file
Checked on GA: CA2266 fires on a multi-file app without the shebang, hence line 1. Including .cs files also works on recent .NET 10 SDKs; DLL includes are 11 only. dotnet run -e is new in general, not only for file-based apps. 11 also adds quoted #:property values and Name=Value metadata on #:package, #:project and #:ref.

CLI and dotnet test

# solution filters (a subset of a solution), from the CLI > dotnet new slnf --parent-solution MyApp.slnx --name Lib > dotnet sln Lib.slnf add src/Lib/Lib.csproj # dotnet test on the new Microsoft.Testing.Platform runner > dotnet test --timeout 90s --maximum-failed-tests 5 > dotnet test dirs.proj --results-directory-layout per-module > dotnet new xunit --xunit-version v3
  • The dotnet command itself is now compiled to machine code ahead of time (NativeAOT): --help and tool launches skip ~600 ms of startup
  • Containers: multi-platform images with Podman, and reproducible builds (same source, same image)
Live display of in-flight tests and per-assembly counts too. Container local-runtime preference changed to wslc / container before Docker: a breaking change for some build scripts.

Part five

ASP.NET Core
& EF Core

No more instrumentation package, no more wasted joins

Two slides each. Pick based on the room.

ASP.NET Core 11

  • Zstandard in the response-compression and request-decompression middleware, enabled by default there
  • OpenAPI 3.2 is the default document version
  • dotnet new mcpserver: a template for an MCP server (tools that AI agents can call), in the SDK
OpenTelemetry.Instrumentation.AspNetCore is no longer needed for the HTTP server span. Opt out with the AppContext switch Microsoft.AspNetCore.Hosting.SuppressActivityOpenTelemetryData. OpenAPI 3.2 is a breaking change if your client generator lags: set OpenApiVersion = OpenApi3_1. Kestrel's non-throwing HTTP/1.1 parser: up to 20-40% more throughput under malformed traffic.

Blazor

  • TempData in static server rendering (no live connection): “saved!” messages after a redirect
  • Client-side and async form validation in static server rendering
  • Interactive Server sessions can pause on inactive tabs (opt-in AddAutoPause)
  • QuickGrid: paging modes, sort and page in the URL, OnRowClick
  • AI chat components (AG-UI protocol) experimental
QuickGrid controls now render as links — a CSS breaking change if you styled the buttons. The WASM dev server is replaced by Microsoft.AspNetCore.Components.Gateway.

EF Core 11

Faster includes

up to 29%

in EF's own benchmark: pruned joins and ORDER BY keys for to-one includes. No code change.

LINQ to SQL

FullJoin → FULL JOIN, MaxByAsync, MinByAsync

Complex types

The preferred way to map JSON columns, now with inheritance mapping and indexes on nested properties. Keyless owned JSON collections are obsolete.

Migrations

dotnet ef database update Name --add: scaffold, compile and apply in one step

The docs' benchmark: one scenario 22% faster with a single query, 29% with a split query; your mileage will vary. Requires the .NET 11 runtime: EF Core 11 does not run on .NET 10. The latest migration ID is now in the snapshot, so diverging branches give a merge conflict instead of a silent mess. SQL Server: vector properties no longer loaded by default.

Before you upgrade

CPU baselinex86-64-v2 everywhere, LSE on Windows Arm64 — old machines fail at startup
Numericsdecimal ↔ double now correctly rounded, no switch to turn it off
HostingIHost.RunAsync throws when a BackgroundService fails
ASP.NET CoreOpenAPI 3.2 default, OpenTelemetry tags on by default
EF CoreSQL Server compatibility level 160; SqlClient 7 moves Entra ID (Azure AD) sign-in to Microsoft.Data.SqlClient.Extensions.Azure
C#union and closed are contextual keywords; with(...) in a collection expression needs @with for a method
The decimal one is the sneaky one: (decimal)1.23 is no longer guaranteed to equal 1.23m bit for bit as before. Financial code with double in the pipeline: test it. Compat level 160 means LEAST/GREATEST etc. — pin a lower level for SQL Server 2019 and older. Press down for the decimal demo.

The sneaky one

# double d = 1.23; decimal m = (decimal)d; Console.WriteLine($"{m} {m == 1.23m}"); PS net10> dotnet run dec.cs 1.23 True PS net11> dotnet run dec.cs 1.2299999999999999822364316060 False

Correctly rounded now: the double's exact value, rounded once. Before, it was rounded to 15 significant digits.

Real output, .NET 10.0.401 vs 11.0.100 GA. Mathematically the new result is the right one, and there is no compat switch. Anything that goes double to decimal and then compares, rounds to cents or hashes: test it.
